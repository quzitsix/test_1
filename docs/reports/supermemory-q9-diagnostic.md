# Q9 笔记诊断：已知结果与下一步

来源：用户粘贴的 `sm-diag-q9-v1-qwen3-vl-8b-memory/adapter_trace.jsonl` 汇总和目标片段笔记，2026-09-11。尚未收到完整诊断归档、原视频或 oracle 结果；不要把 memory 完成等同于两轨都完成。

## 可以确认的事实

- 18 次生成笔记：988.36 秒，10,882 个输出 token；平均每条约 605 tokens、54.9 秒。
- 1 次回答：1.71 秒，2 个输出 token。最终回答是 D（无法回答），原题 Q9 的官方正确选项为 A。
- 此前汇总记录 encode 1.983 秒、transfer 0.211 秒、sample 2.82 秒。主要时间在笔记的 generate 调用内，不在抽帧或 processor 编码阶段。
- 4/18 条笔记达到 900-token 上限，并非全部笔记都触达上限。10,882/988.36 ≈ 11 tokens/s 是包含视觉编码、预填充的平均输出吞吐，不能当纯文本解码速度。
- Q9 目标片段内的实际采样是 7.5、22.5、37.5、52.5 秒，尺寸全部为 768×768。该片段覆盖原录制 240～300 秒，因此对应 247.5、262.5、277.5、292.5 秒。
- 官方证据区间是原录制 248～267 秒；四帧中只有 262.5 秒落在区间内。

## 这条笔记说明什么

目标片段笔记描述了冰箱、人物、沥水篮、厨房设备和拿着红洋葱的动作，却没有记录红色网袋被丢弃及其去向。它提到的“冰箱内红色塑料袋”不能直接认定为原题中的空网袋。

**可以确认这条笔记没有保留解答 Q9 所需的事实；不能确认原因。** 单个采样点落在标注区间内，不等于拍到丢弃动作或目标垃圾桶。动作可能发生在两帧之间，目标可能被遮挡，模型也可能看到了却漏记。另一种情况是其他 17 条笔记有补充或冲突，回答阶段未正确使用；目前提供的单条笔记不足以排除这一点。

笔记包含许多品牌、颜色和人物动作细节，但在核对图像前不能断言这些都是幻觉。“第一人称／第三人称”的说法也不足以证明视频来源错了：第一人称画面里本来就可以看见另一位人物。

## 先看实际四帧和连续视频，不重跑模型

新增 `scripts/make_hf_observation_review.py`，在服务器上用原运行对应的准备视频重建观察页。页面包含：

1. 原题、原选项、模型回答与可展开的官方答案；
2. 可播放的完整 60 秒准备片段，默认定位到标注区间起点；
3. 与 trace 时间和尺寸一致的四幅 PNG；
4. 目标片段笔记，以及可展开的本环境全部笔记。

工具校验运行／题库指纹、题目、媒体 SHA、片段索引、时间戳、图像尺寸和最终回答，并选择最近一次完成回答的进程和环境尝试。图片是从同一媒体重建的 **processor 之前的 RGB 输入**，不是历史保存的帧快照，也不是模型内部张量；不同解码库版本仍可能产生像素级差异。此工具只读原视频、结果和 trace；输出写到独立的 review 目录，不运行 VLM，不作为新的评分输入。

先确认原实验两轨已结束。`logs/sm-diag-q9-v1.log` 末尾应有 `Completed tag: sm-diag-q9-v1`；如果 oracle 还在运行，先保持当前 checkout 版本不变，完成后再更新：

## 根据核查决定下一轮实验

| 核查结果 | 下一步 |
|---|---|
| 连续视频有动作，四帧没有足够证据 | 做统一提高采样密度的消融；不能只按答案时间给正式模型挑帧 |
| 四帧已清楚呈现去向，笔记没有保留 | 调整记忆写入策略，优先记录动作、对象和目的地，同时检查笔记长度 |
| 全部笔记中已经有正确去向，仍选 D | 调查笔记冲突、信息组织及回答阶段 |
| 连续片段也无法支持官方答案 | 记录标注／视频对应关系的疑点，人工审核；先保留原题和原评分，另列审计结果 |

缩短 `note_max_new_tokens` 是可以做的速度消融，但不是已经验证的正确性修复；过短可能丢失更多信息。采样和笔记预算应分别改变并使用新 tag，才能区分哪项改变带来影响。当前没有新增大规模模型运行，也没有修改原题、gold 或正式评分。

本地新增 7 项回归通过：媒体／时间／回答不匹配时拒绝生成、片段索引一致性、原文件不变、输出目录保护、HTML 转义和重试尝试选择。测试使用合成短视频，没有下载真实视频或模型；服务器画面内容仍待人工核查。
